# 微信独立用户隔离

## 1. 隔离单位与启用方式

本模式适用于“每个用户分别扫码绑定自己的 Bot”。隔离单位为渠道、Bot 账号及绑定的微信 Bot 身份。同一个 Bot 内的多个发送者仍共用该 Bot 的长期记忆，不应把同一个 Bot 分配给不同的独立用户。

外部服务调用 `POST /api/weixin/binds`，绑定成功时自动将该渠道的 `settings.isolate_accounts` 设为 `true`，配置重载后生效。**这会同时隔离该渠道内已有的 Bot。** `confirmed` 表示凭据已保存，不能据此认定运行时已经重载成功；还需要检查网关日志及实际收发。

通过 CLI、Web 配置页绑定的已有渠道，可手动启用：

```json
{
  "channel_list": {
    "weixin": {
      "enabled": true,
      "type": "weixin",
      "settings": {
        "isolate_accounts": true
      }
    }
  }
}
```

这是现有配置上的增量片段，需保留原有 Bot 账号和凭据。字段未配置时继续使用原有共享 Agent 分发逻辑。外部绑定接口始终启用隔离；需要保留共享模式的个人渠道，请通过 CLI 或管理页绑定。

## 2. Agent、会话与记忆

- 每个启用且已绑定的 Bot 自动创建一个运行时 Agent，不需要手工维护 `agents.list` 或 dispatch 规则。
- 该渠道的消息优先进入独立 Agent，普通 dispatch 规则不能将它改回共享 Agent。
- 独立目录位于规范化为绝对路径后的默认 workspace 的同级 `weixin-users/weixin-user-<身份摘要>/`。尾部分隔符和相对路径不会使目录嵌套进共享 workspace。目录名不包含令牌或用户原始编号。
- 隔离校验还会按实际 workspace 解析所有非隔离 Agent（包括 `agents.list` 中覆盖默认目录的 Agent），只要共享 Agent 工作目录与派生根或用户目录真实重叠，就拒绝创建隔离 Agent 和共享回退。
- 校验会解析共享目录、派生根目录及用户目录已有祖先的符号链接，尚未创建的层级按真实祖先补齐。已有目录按文件系统身份检查，互相包含或相同时拒绝创建隔离 Agent，大小写别名不能绕过；尚未创建且仅大小写不同的潜在重叠目录也会被拒绝。用户目录不能链接到共享目录、其他用户或其他位置；断链、链接循环及非目录路径也会被拒绝。合法的共享目录或派生根目录链接保留原配置位置，不迁移数据。
- 渠道按原始配置键精确查找并参与身份摘要，支持 `WeixinBusiness` 等大写名称；仅大小写不同的渠道也分别隔离。
- 长期记忆、每日笔记、会话历史及摘要、工作文件分别保存在各自目录内。
- 隔离会话固定按 `chat`、`sender` 划分，不使用全局 `session.identity_links`。
- 历史读取、压缩、摘要、旁路提问和清空操作均使用当前路由确认的 Agent，不根据工作目录内可修改的会话元数据重新选择存储。
- 排队消息的自动续接保留内存中的可信账号、会话及 Agent 归属，续接前重新校验绑定；禁用、删除、换绑或实例不可用时拒绝续接，不从可写元数据恢复隔离路由。
- 独立 Agent 使用全局默认模型及其回退、图片和轻量模型配置，不继承共享 Agent 的用户资料、记忆、技能或工作目录提示词。

未知、禁用、未绑定的 Bot，以及初始化失败的独立 Agent，会拒绝处理消息，不回退到共享 Agent。其他渠道也不能通过普通 dispatch 规则访问这些独立 Agent。

隔离模式目前仅支持 `agents.defaults.context_manager` 留空或设为 `legacy`。`seahorse` 及其他插件后端仍使用共享存储，因此不会创建隔离 Agent，并拒绝对应消息；配置重载后也会检查实际运行的上下文后端。切换后端需要重启网关。

即使渠道配置了 `reasoning_channel_id`，隔离 Agent 也不会向该共用会话转发推理内容。重载配置或关闭隔离后，已开始的隔离回合仍受此限制。普通回答和独立会话中的推理记录遵循现有逻辑。

## 3. 工具与管理权限

独立 Agent 开放已启用的 `read_file`、`write_file`、`edit_file`、`append_file`、`list_dir`、`web_search` 和 `cron`；文件读写范围仍固定为自己的工作目录。搜索遵循 `tools.web.enabled` 及搜索服务配置，定时任务遵循 `tools.cron.enabled`。`AGENT.md` 声明和 turn profile 可进一步收紧工具。

全局 `restrict_to_workspace=false`、目录外读取开关、路径白名单均不能放宽这一限制。嵌套符号链接仍受文件工具的越界检查约束。

入站附件记录所属 Bot 身份，解析时校验与当前隔离 Agent 一致，再复制到其 workspace 的 `.inbound-media/` 供 `read_file` 读取，不扩大临时目录白名单。当前回合的图片在归属校验后直接作为视觉输入发送给配置的图片模型；未单独配置时使用当前模型，需要该模型支持视觉输入，无需开放 `load_image`。历史图片不在后续纯文字回合重新编码。副本遵守媒体大小上限，并防止符号链接越界；重建提示词复用同一副本。副本随用户目录保留，清理由服务端管理。

命令执行、MCP、主动消息、文件发送、技能安装、跨 Agent 调用等工具不会注册。定时任务仅支持提醒和隔离 Agent 问答，不支持 Shell 命令；即使配置远程命令白名单或传入 `command_confirm=true` 也不能绕过。任务创建时原子保存渠道、聊天、Bot 账号及 `isolation_agent_id`；远程用户只可管理当前聊天、账号和绑定身份的任务。换绑、删除账号或关闭隔离后，旧任务拒绝执行与投递，不回退共享 Agent；开启隔离前的未绑定旧任务也不会自动迁入。任务仍由服务端统一存储于 `<共享 workspace>/cron/jobs.json`，不会复制到用户目录。用户修改自己的 `AGENT.md` 只能进一步收紧工具范围，不能增加权限，也不能据此改用本机模型。

网络搜索通过客户端 `web_search` 工具开放；`web_fetch` 和模型原生搜索仍禁止，即使全局开启 `web.enabled` 和 `prefer_native`，回退候选模型及调用钩子也不能开启原生搜索。搜索查询会发送给管理员配置的搜索服务，应避免在查询中包含隐私数据。

隔离 Agent 不出现在其他 Agent 的可调用列表中，其名称和描述不会通过 Agent 发现机制注入共享提示词。

聊天命令只开放 `/help`、`/start`、`/clear`、`/context`、`/stop`、`/btw`、`/use`。不允许查询其他 Agent、切换模型或重载网关。技能只从自己的 workspace 加载。

隔离 Agent 不参与自动技能演化，包括回合后的记录、后台召回与草稿生成，以及定时冷路径扫描；即使回合结束前发生配置重载、换绑、删除账号或关闭隔离，原隔离回合的完成事件也不会重新进入演化；共享 Agent 的技能演化不受影响。

`claude-cli`、`codex-cli`、`github-copilot` 等可能执行本机操作的模型不支持本模式，包括主模型、回退模型、图片模型和轻量模型。同一模型别名的全部候选配置均须通过检查；任一候选不安全时，独立 Agent 不启动。启动和重载保留原始模型配置引用及协议，隔离 Agent 据此创建 provider，不复用共享 Agent 注入的 provider。共享 workspace 的 heartbeat 任务也不会发送到隔离 Bot。

配置中的模型别名保留用于选择模型；实际对话、旁路提问和摘要请求使用所选配置中的模型 ID。共享 Agent 的启动与重载会把已选配置一并传入，保证 provider、端点、凭据、模型 ID 和思考设置对应同一个候选。

这是应用层的数据和工具隔离。网关管理员、同进程的可信扩展、模型服务配置及宿主机权限仍属于服务端信任边界；需要运行不可信代码或更强隔离时，应使用独立进程或容器。

隔离定时任务执行期间不向渠道发布工具反馈，包括模型正文和工具参数预览；最终结果在执行结束后重新校验原绑定身份，通过后才投递。普通入站对话的工具反馈仍遵循全局配置。

## 4. 重启、换绑与迁移

同一微信 Bot 的令牌刷新保留原目录；换绑为另一个微信 Bot 身份会生成新目录。优先使用微信 Bot ID，缺失时使用微信用户 ID，再缺失时才用令牌参与摘要，最后一种情况下换令牌也会换目录。

入站消息记录接收时的绑定身份。换绑、删除渠道或关闭隔离后，队列里遗留的旧身份消息会被拒绝，不会转交给新用户或共享 Agent。

重启和配置重载会根据绑定身份重新找到原目录。删除 Bot 不自动删除用户目录；数据清理和保留期限由服务端管理。

开启隔离不会搬迁历史共享记忆或聊天记录，避免把混合数据复制给独立用户。确需迁移时，应先确认数据归属，只迁移该用户自己的内容。

回滚时可恢复原代码或关闭渠道的 `isolate_accounts`，然后重载；独立目录保留。关闭隔离会重新进入共享模式，不适合继续向独立用户开放。外部扫码绑定成功会再次启用隔离。

## 5. 容量与业务系统责任

单渠道仍最多 64 个 Bot。接收消息继续复用轮询调度器与 HTTP 连接池，但每个独立 Agent 有自己的上下文、会话存储和工具注册表，不能沿用只有连接状态时的每 Bot 内存估算。

业务系统仍需校验当前业务用户对 `channel/account` 的操作权限，并持久化绑定关系。`bind_token` 是服务端渠道密钥，不能交给访客浏览器；`external_id` 是关联字段，不是用户授权凭据。

## 6. 验证清单

- 两个 Bot 的长期记忆、文件及相同键的会话历史互不共享。
- 连续两轮对话可以读取自己的上一轮历史；摘要和压缩只操作所属 Agent 的存储。
- 配置 `reasoning_channel_id` 后，两个隔离 Bot 在普通回答和工具调用回合均不向共用会话转发推理；共享模式仍可正常转发。
- 配置重载后更换推理目标会话，或关闭渠道隔离，已开始的隔离回合仍不向共用会话转发推理。
- 在自己的目录伪造其他 Bot 会话键的元数据和历史后，不能影响对方的对话、旁路提问、摘要、压缩和清空。
- 修改自己的会话归属后，排队消息仍由原隔离 Agent 续接；绑定变更或可信路由缺失时拒绝续接。
- 客户端搜索定义在普通、钩子和回退模型请求中可见；全局启用原生搜索及调用钩子尝试开启时，隔离模型调用仍不携带原生搜索选项。
- 定时任务持久化保存账号及原绑定身份，同聊天的其他 Bot 无法查看或管理；命令调度、换绑、禁用、删除账号或关闭隔离均不能使任务越权执行。开启工具反馈后，任务执行期间不发布中间反馈；执行中换绑时，中间反馈及最终结果均不进入出站队列。
- 同别名混合 HTTP/CLI 候选时拒绝启动，隔离实例不复用共享 provider。
- 未设置默认 provider 时，非 OpenAI 模型别名在启动和重载后均可正常响应。
- 同名别名配置多个模型或端点时，主 provider、实际模型 ID 和思考设置沿用同一次选择，启动与重载后的 `/btw` 也沿用该配置，不再次轮询别名。
- Legacy 与 Seahorse 摘要使用实际模型 ID；Seahorse 在模型切换或配置重载后使用当前 provider。
- 开启技能演化后，隔离回合和目录不会进入后台记录、召回、生成或定时扫描；重载期间结束的旧隔离回合同样会被过滤。
- 目录外读取、写入、列目录和符号链接越界被拒绝，即使全局配置允许。
- 默认 workspace 带尾部分隔符或为相对路径时，派生目录仍位于共享目录之外；无法分离时拒绝创建。
- `agents.list[*].workspace` 覆盖默认目录、主 Agent 或其他共享 Agent 的实际 workspace 与隔离目录重叠时，拒绝隔离实例和共享回退；普通共享 Agent 工作目录独立时仍可正常启动。
- 共享目录链接到父目录、派生根链接到共享目录或其祖先、用户目录链接到共享目录或其他用户时，拒绝隔离实例和共享回退；大小写别名也不能绕过。目录未创建及合法符号链接仍可正常使用，但仅大小写不同的潜在重叠目录会被拒绝。初始化后出现目录重叠时，后续消息同样拒绝处理。
- `seahorse` 和其他共享上下文后端下不创建隔离 Agent，也不能通过配置重载绕过。
- 大写渠道可正常创建和路由到独立 Agent；大小写不同的配置键不共享身份。
- 本人附件在 workspace 内可读取，其他 Bot、无归属和旧绑定附件被拒绝，复制路径不能通过符号链接越界。
- 本人的当前图片可作为视觉输入送入图片模型，历史图片不会在后续纯文字回合重新编码，超限图片与归属不符的图片不能进入视觉输入。
- 新增或隐藏注册的高权限工具、工作目录提示词修改、管理命令不能绕过限制。
- 未知账号或独立 Agent 缺失时拒绝回退；其他渠道不能直接访问独立 Agent。
- 重启保留各自记忆；同身份刷新令牌不换目录，换绑其他身份使用新目录。
- 外部扫码绑定成功保存隔离开关；配置保存、加载后开关及目录分配保持一致。
- 正式部署后还需双微信账号实测和并发容量压测。
